## Reporting a Vulnerability

**Please do not open a public GitHub issue for security problems.**

Instead, use **GitHub Private Vulnerability Reporting**:

1. Open the **Security** tab of this repository
2. Click **"Report a vulnerability"**
3. Describe the issue with as much detail as possible

If that is unavailable, contact the maintainer via the contact links on the profile page associated with this repository.

### What to include

- A clear description of the issue
- Steps to reproduce
- HardMon version (see **About** dialog inside the app)
- Windows version and build
- Any proof-of-concept, screenshots, or logs (**redact personal data**)

### What to expect

| Stage | Target timeframe |
|---|---|
| Acknowledgement | within 72 hours |
| Initial triage | within 7 days |
| Fix or mitigation | best-effort, timeline shared in the report |
| Public disclosure | coordinated after a fix ships |

We follow responsible disclosure. Please give us a reasonable window before making the issue public.

## Binary Integrity

Because the download archive is **password-protected and redistributed as a raw binary**, integrity verification is important.

Verify on Windows:

```powershell
Get-FileHash .\HardMon.exe -Algorithm SHA256
Get-FileHash .\HardMon_1.0.0_Windows_x64.zip -Algorithm SHA256
```

If a hash does not match, **do not run the file**. Re-download from the official landing page only.

## SmartScreen & Antivirus Warnings

`HardMon.exe` is **not code-signed** with an EV certificate. As a result:

- **Windows SmartScreen** will warn on first run → expected, verify hash, then run
- **Some AV engines** may flag unsigned/new binaries → verify hash, then whitelist
- **No** network traffic is generated by the application itself

If your scanner flags the binary, please report it to the vendor using the hash from this file so they can whitelist it.

## Privacy

HardMon is **privacy-first**:

- No telemetry
- No analytics
- No identifiers
- No cloud calls
- No background services

If you observe network activity attributed to `HardMon.exe`, treat it as a security incident and report it via the process above.

---

## Permissions

HardMon runs as a **standard user** by default. Optional elevation (running as administrator) unlocks additional temperature sensors but is never required for CPU / RAM / disk / network monitoring.

HardMon does **not**:

- Install drivers
- Register services
- Modify the registry beyond standard per-user config
- Create scheduled tasks
- Persist beyond its own folder
